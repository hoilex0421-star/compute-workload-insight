# 五种页型与内容槽位

本技能提供五类分析结构。C型附有可编辑PPT示例；A/B/D/E为文字布局规范，按任务需要选择，不要求每次产出所有页型。

## A 研究工作流

**要回答：如何把趋势持续转化为系统需求，环节之间交付什么？**

标题下红色横线；在扣除页边距的内容区内，主体左侧约60%，右侧约37%，中间约3%。左侧为纵向流程，右侧是所选关键环节的职责与交付物。

左侧顺序：趋势与场景捕获；模型/负载拆解；Infra架构与优化；建模分析；Benchmark；系统与芯片需求。上游来源可分组，下游归并，避免全部画成平行方框。

右侧每个说明块使用“职责＋交付物”，例如模型实现、配置、负载Trace、建模假设、验证结果。负责人、平台、组织名均由用户材料填写。

**不要：** 把样张中的人员姓名和内部平台固定进后续页面；无职责材料时编造负责人。

## B 全景路线矩阵

**要回答：跟踪哪些方向，各方向解决什么挑战，成熟到什么程度？**

按模型家族分泳道，左侧约12%写领域，中间约43%放演进方向与技术项，右侧约41%放驱动力与成熟度判断。某一行需要更多技术项时可横跨中右区域，不能为统一宽度强行压字。

每条泳道内部结构：技术挑战；演进方向；候选技术；关键依据；时间/成熟度。不同方向可分成2—4组，以材料为准。多于五个家族时优先分组，必要时分页。

底部保留统一图例：当前、近期、中期、远期，或用户确认的代际。颜色只编码该页明确选择的一个语义，不混用“成熟度”和“供应商”。

**不要：** 把演进方向写成无关联的术语清单；仅凭颜色断言商业化年份。

## C 标准专题洞察（默认母版）

**要回答：一个模型家族的技术演进如何改变计算系统需求？**

```text
┌───────────────────────────────────────────┐
│ 主题：技术演进与系统需求                     │
├───────────────────────────────────────────┤
│ 总结 │ 模型趋势                             │
│      │ 系统需求                             │
├─────────────────────┬─────────────────────┤
│ 演进趋势             │ 技术—Infra—系统需求表 │
│ 规模/关键变量/拐点    │ 指标、条件、验证状态   │
├────────↓────────────┴──────────↑──────────┤
│  技术T1证据       技术T2证据       技术T3证据 │
│  机制/变量/公式/假设/结果/边界                │
├───────────────────────────────────────────┤
│ 来源短标 / 必要口径 / 页码                  │
└───────────────────────────────────────────┘
```

快速阅读顺序：顶部总结、左侧趋势、右侧需求。深入核查顺序：趋势、底部建模、右侧需求。

| 区域 | 内容槽位 |
|---|---|
| 标题 | 对象＋变化主线或系统影响；可沿用“X：关键技术演进及系统需求” |
| 总结 | 模型/应用趋势；有条件的系统需求 |
| 左上 | 当前点、情景点、时间/代际、关键指标、技术拐点 |
| 右上 | 技术、Infra优化、系统需求与条件 |
| 下部 | 通常2—3个技术机制与量化证据块；数量服从证据，不凑满三项 |
| 页脚/备注 | 来源、数据状态、必要口径；详细计算与资料放备注 |

趋势图纵轴可用参数量，也可用序列长度、稀疏率、去噪步数或并发。跨数量级的图需明确对数/线性刻度；定性路径不能伪装成数值曲线。区分观察与预测的线型或标记。

底部卡片依次写技术标题、证据/机制、变量及假设、模型或结果、边界。内容不足时保留定性机制和验证状态，不能复制其他技术公式补空。

## D 定量建模

**要回答：哪些变量决定瓶颈，给定工况下系统需要满足什么约束？**

顶部标题与总结；上半部通栏路线/规格表；左下当前值与情景假设；右下测算结果与系统约束；中间箭头表示假设进入模型。

上表按模型/路线/变化维度/时间组织。若时间比较不关键，可以改为工况或配置比较。左下变量表最少有变量、定义/单位、当前值、情景值、依据。右下先展示结果，再将结果解释成瓶颈和指标。

适合多路线物理AI、多分辨率视频、不同batch/序列、不同缓存策略等问题。

**不要：** 把同一带宽需求同时解释为单卡HBM与集群网络；没有工况时输出唯一规格数字。

## E Agent系统专题

**要回答：交互与工具执行方式变化，把压力转移到了哪些资源？**

左栏约42%，右栏约52%，中间约2%；页面边距另计。左上业界进展，左下能力/技术演进；右上机制、场景观测和局部结论；右下Infra和系统需求。

左上产品案例按统一字段比较，资料不全时减少案例。左下可分别展示规模变量与机制演进，例如上下文、并发、沙箱；外部编排与模型内化仅在资料支持时使用。

右上先交代序列/缓存/工具调用的变量定义与机制，再给测量口径一致的场景数据，然后提炼局部结论。右下区分GPU模型推理、CPU工具执行、缓存、运行环境的需求。

**不要：** 将缓存命中率直接当作总计算节省率；将累计创建的沙箱数当作同时活跃数量；把单实例启动延迟与大规模扩容准备时间混用。

## 组合原则

五种页型代表五类功能，并不代表任何专题都需要五页。用户要一页时，优先C/D/E；要完整研究时可先B交代全景，再按主题用C/D/E；仅在说明研究机制或分工时添加A。
