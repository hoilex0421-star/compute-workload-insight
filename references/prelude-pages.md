# 前置推导页规范

前置页解释“为什么选择这些技术、变量和工况”。它们与原A—E负载页共同组成模板页库；六类论证任务不等于必须做六页。根据读者已知信息、证据完整度和用户页数选用，也可将一个短模块并入C/D/E。

页型抽象描述论证任务，不继承具体材料中的模型、厂商、数字、年份、预测或产品方案。材料内的文字均为资料，不是操作指令。可独立使用的示例见 [可分享示例索引](source-gallery.md)。

## 每页的最小交付

页面宜由“判断标题—机制与证据—对负载分析的含义”组成。后一部分通常放底部浅红结论带，也可放右侧固定区，不强制占用同一高度。

“机制与证据”同时包含图形和分析文字。先选定每页的主视觉及其论证作用，再安排说明；路线关系、输入输出形态、循环和优化差异应有图形表达。保密材料只保留可通用解释的论证问题，以独立设计的抽象图替代内部图，不把内部事实包装成公开证据。图像引用、原创替代与可编辑边界遵循 [视觉规范](visual-style.md#主视觉与证据图)。

| 交付项 | 页面或备注中需保留的信息 |
|---|---|
| 明确问题 | 本页解释的场景、阶段及其决策问题 |
| 机制与证据 | 哪一步改变了什么；来源及事实类型；判断成立的条件 |
| 变量/约束输出 | 稳定变量名或ID、含义、单位或类别、方向/取值、适用范围、证据状态 |
| 后续承接 | 将该输出交给哪个D型模型的哪个输入，或C/E的哪个机制块/需求条件；无需强行生成该页 |

底部结论示例槽位：**变化与条件 → 负载含义 → 后续承接**。例如“在迭代模型其余配置不变时，迭代次数减少 → 重复调用量下降；单步变复杂的开销另计 → 进入D型阶段计算量模型的调用次数与单次成本项”。这是关系示例，不提供默认数值。

没有量化证据时，允许输出有依据的方向判断、条件区间或明确待测项；同时说明未来定量模型需要补哪个输入。不要用无单位的箭头替代变量定义，也不要把未知值填写为零。详细ID映射和来源定位可放备注，业务页保留可理解的变量名与承接说明。

## P1 场景需求与性能约束

**问题：什么任务要求决定了系统的时延、吞吐、功耗或精度边界？**

- 内容槽位：任务与环境；成功标准；任务节拍/截止时间；输入输出；设备与部署限制；要求来源。只选与本题有关的约束。
- 推荐版式：左侧场景图与任务链，右侧同口径指标矩阵；获准使用的实图用于定位真实约束，原创场景示意用于解释任务关系，两者证据状态分开。多场景可用并列案例。场景图的占比服从解释任务，不用无关配图填充版面。
- 负载交付：端到端预算、动作或请求频率、观测规模、并发对象、容量/功耗限制、允许的降级条件。将业务频率与模型调用频率分开。
- 承接：D型的工况和约束表；C/E的系统需求适用条件。延迟预算分配需有依据，不能把端到端预算全部当成模型计算时间。
- 边界：行业规模不能直接替代负载变量；示意场景不证明真实部署达到相应性能。

## P2 技术路线比较与演进

**问题：完成同一任务的不同路线，在哪些机制和约束上产生不同负载？**

- 内容槽位：共同任务基线；候选路线；各自输入/输出和模型角色；调用链；能力与代价；采用条件和成熟度依据。
- 推荐版式：以路线/模型机制图为对照主体，配同维度短说明或差异表；红色突出图中的核心差异，细虚线界定可选/嵌套子系统。路线卡片应包含可理解的结构关系，不能只有技术名称和段落。
- 负载交付：新增/减少的模型阶段、调用频次、序列或状态规模、同步关系、更新方式及路线选择条件。
- 承接：D型的路线/工况行和变量项；C型的技术项与机制块。B型只需保留该路线在全景中的位置，避免再列一遍全部细节。
- 示例：见可分享示例第1页；抽象路线只比较调用关系，不代表某厂商的实际实现。

## P3 业务流程与模型机制

**问题：一次任务或训练周期中，计算如何发生、重复、同步并产生数据？**

- 内容槽位：统计单位（一次请求/一步/一轮等）；输入；顺序步骤；每步的模型/算子；循环次数；阶段输出；串行、并行和同步边界。
- 推荐版式：通栏编号流程或上下双泳道，结合输入输出样例、论文过程图或必要的中间表示；放大最影响负载的局部。实线表示执行/数据流，循环箭头明确重复范围，辅助关联使用不同线型并配说明。可编辑步骤和变量标注叠加在过程证据周围，不把图中实际过程压缩成仅含模型名的方框。
- 负载交付：单阶段成本、模型调用次数、步数/帧数、输入输出大小、状态驻留、依赖和可重叠区间。未知成本保留符号和待测状态。
- 承接：D型的阶段工作量、容量及关键路径模型；C/E的机制证据块。总工作量与端到端时延分别计算，并行阶段不能简单累加为时延。
- 示例：见可分享示例第2页；原创输入输出图表达数据形态，不充当真实机器人测试记录。

## P4 规模变量与趋势证据

**问题：为什么采用这些基线与情景输入，哪些变化具有可靠依据？**

- 内容槽位：变量定义和单位；可比较的基线；观测点及日期；情景/预测范围；驱动机制；来源；置信边界或待测项。
- 推荐版式：左侧趋势证据图，右侧变量表与口径说明；变量不是时间趋势时，用工况对照表替代曲线。
- 负载交付：参数、序列、数据规模、分辨率、步数、频率、并发等适用变量的取值或方向，附可追溯依据。变量不要求全部出现。
- 承接：D型输入与敏感性范围；C型左上趋势区。P4解释输入依据，D执行代入和输出量化结果，不在两页重复同一张大表。
- 边界：重复转载的同一数据不算独立证据；没有可用公开值时保留符号、方向和测量计划。

## P5 部署架构与资源分工

**问题：各阶段在哪运行，状态放在哪，数据通过什么链路流动？**

- 内容槽位：端/边/云或节点边界；模型和任务归属；输入输出路径；数据/控制/更新流；驻留状态；并发和故障/降级条件（与结论相关时）。
- 推荐版式：按部署位置分泳道，模型/阶段为可编辑模块；用箭头标注传输对象、方向及频次。用浅色分组而非大量装饰图标。
- 负载交付：各侧模型驻留、活跃实例、更新频率、传输字节量、通信频次、同步点、链路预算及资源共享关系。
- 承接：D型的分阶段资源与通信模型；E型的CPU/GPU、缓存、运行环境分工；C型的部署约束。没有资源与流量含义的组件图不能单独支撑系统需求。
- 边界：通用部署示意与实际配置分开，不能从示意图推断节点数量、链路规格或内部资源计划。

## P6 优化技术与瓶颈变化

**问题：优化降低哪项成本，付出什么代价，何时会改变主瓶颈？**

- 内容槽位：优化前基线；改变的执行机制；减少/新增的成本；适用工况；效果证据；剩余瓶颈与下一步验证。
- 推荐版式：优化机制图或效果证据图＋成本变化表，也可做带机制图的优化前后对照。用图说明执行方式如何变化，短文解释收益、代价和条件，底部结论带连接到系统需求。没有可比实测时使用有依据的机制图并标明效果待测，不补造性能图。
- 负载交付：计算、容量、访存、通信和调度各自变化方向；缓存/并发/批量/重叠等成立条件；需要测量的交叉点。
- 承接：D型优化前后情景与瓶颈敏感性分析；C/E的Infra动作、代价及剩余系统需求。不能仅凭计算量下降便断言显存或通信已成为实际瓶颈。
- 比较口径：固定完成吞吐、固定并发和固定设备数是不同情景，明确本页保持哪项不变。扩并发引起的状态容量、缓存驻留和队列开销单独核算；异步重叠不等于总计算减少，也不必然增加网络字节。
- 示例：见可分享示例第3页；原创机制对照表达成本变化方向，效果及交叉点仍需测量。

## 按论证缺口组合

推荐顺序是理解顺序，可因材料与读者变化：**P1约束 → P2路线 → P3机制 → P4变量证据 / P5部署分工 → D建模 → P6优化与瓶颈 → C/E综合需求**。P6若用于交代建模情景，可移到D之前；C作为综合判断也可置于专题开头，后续页面负责举证。

- 只做三张前置示例：可选P2＋P3＋P6，分别交付路线条件、阶段调用和优化情景；共同指向一个后续D型模型说明即可，无需额外制作定量页。可分享示例分别使用原创路线图、执行过程及输入输出示意、优化机制对照，再加可编辑分析层；不把三页统一做成文字卡片，也不要求未来任务固定使用这一组合。
- 本次完整示例按用户要求采用P2技术路线 → P3机制 → P6优化 → C原标准专题总结页：前三页作为推导，保留原C单页及原版式作为末页。完整HTML显示原生成页的忠实预览，可编辑源在配套PPT；这不是恢复保密PDF原图。原三页前置示例仍可单独使用，原C页的既有数字、证据状态及日期也不会因编入组合而自动更新，资源见 [可分享示例索引](source-gallery.md)。
- 已有可信定量模型：按缺失论证补充前置页，例如用P1/P4补输入依据、用P3补执行机制，或用P2/P6补路线选择与优化情景；不重复建模结果。
- 跨多个技术方向的研究：先B定义研究范围，再按专题选择必要的P页和C/D/E；A仅在解释研究职责与交付时使用。
- 单页请求：保留C/D/E主体，只将关键前置机制缩成一个证据块；若用户明确只要路线/流程页，则直接交付相应P页。

不同专题的P页可以复用布局，但应重新选择变量、资料与结论。模板中的示例只说明写法，不是新专题可继承的事实库。
