# HTML交付规范

用户选择HTML、网页阅读稿或离线阅读材料时读取。HTML改变交付与阅读方式，不改变推荐门槛、证据口径或任务范围。

## 交付形态

- 优先交付一个可直接在本地浏览器打开的 `.html` 文件，内嵌CSS、必要的脚本和原创SVG；没有网络也能阅读与操作。
- 不依赖CDN、远程字体、图表服务或远程图片。必须引用的图片在许可范围内内嵌，或按用户接受的方式附本地资源包；不得把缺资源的文件称为自包含。
- 完整阅读稿可采用16:9逐页浏览；长报告或窄屏任务可以采用连续阅读。页数、密度和目录服从用户任务，不固定为示例三页。
- 核心判断、正文和来源说明为真实HTML文字；比较表用语义化表格；关系图、机制和时间轴优先使用SVG。文字可修改不等于可编辑PPT，图像内原有文字仍属图像。
- 用户只要正文或提纲时仍先交付正文或提纲，不自动制作HTML文件。制作本地文件不包含公开托管、发布网站或更改分享权限。

## 内容与图文关系

先确定每页支持哪一个决策问题，再选择主图。图示应有具体作用，例如解释协同如何实现、比较采购与投资的权利差异，或展示现有证据到下一阶段验收之间的路径。

沿用“判断 → 证据 → 投资含义 → 条件与下一步”的层次。来源与限制可收纳到依据面板，但会改变决策的风险、冲突和推荐条件必须在正文可见，不能只放弹窗。

在正文保留公司陈述、样本测试、分析推断和未来目标的区别。配色也可标明不同状态，但需同时使用文字，不能仅凭颜色识别。

示例 [investment-example.html](../assets/investment-example.html) 演示摘要、合作方式比较、缺口与里程碑三种组合，以及翻页、放大和依据面板。其企业与数据均为虚构练习，不能成为新项目的事实来源。无需按示例固定页序、行业、数字或测试门槛。

## 阅读与交互

- 提供清楚的页码、上一页/下一页和直接选页；键盘方向键或PageUp/PageDown与按钮行为一致，在首尾边界不越界。
- 适配整页视图，同时为小屏提供可读的连续或原尺寸阅读方式。不要将所有内容缩到不可辨认，也不通过溢出隐藏裁掉正文。
- 图示放大应有标题、关闭按钮和Escape关闭行为。关闭后返回原页与原控件；弹窗不应改变当前页。
- 依据回看显示与当前主张相关的来源、时间、状态、定位和证明范围。没有原件就明确说明仅获转述；虚构示例只显示虚构依据说明。
- 当前页、交互按钮和弹窗具备可理解标签与可见焦点；弹窗关闭后恢复焦点。动态页面切换更新可见内容及无障碍状态。
- 若增加打印功能，打印时展示所有内容页、移除工具栏和弹窗，各页保持完整且无空白尾页。不要声称未经检查的PDF导出已通过验收。

## 源材料与分享边界

当前任务不上传用户原始模板。技能的GitHub版本只包含通用写作方法、原创交互结构和明确虚构的示例，不包含原PDF、页面图片、逐页样本分析、原文件路径或可识别项目细节。

检查HTML源码中的内嵌图片、Base64、SVG中的 `<image>`/`<use>` 引用、隐藏DOM和脚本数据，不能只检查目录扩展名。不得直接复制含原稿图像的参考HTML。其他任务的引用图片是否可随材料分享，按该任务用户授权判断。

## 浏览器验收

1. 逐页检查常用桌面视口下的标题、正文、图表、来源区，确认没有重叠、裁切或与标题不一致的图示。
2. 检查窄屏和原尺寸/连续阅读方式，核心文字无需放大图示才能读懂。
3. 操作页码与前后翻页，检查键盘、页码更新、首尾边界及隐藏页状态。
4. 放大每类图示并关闭；打开依据面板后返回，确认页码和焦点正确。
5. 检查无外部依赖；在离线状态打开文件，确认图示、文字和交互完整。来源网页链接可以离线不可访问，但本地依据摘要仍须可读。
6. 若提供打印，检查所有页面完整显示以及实际打印分页。

验收应使用真实浏览器。不能用DOM计数或截图文件已生成，代替对可读性和布局的实际检查；缺少浏览器时报告未完成的检查。浏览器验收仅证明呈现与交互，不证明投资判断或事实正确。
