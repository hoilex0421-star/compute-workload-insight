# 论证与页型

搭框架、组织逐页文案或检查主线时读取。下列问题按决策需要选择，不要求每项独占一页，也不要求输出完整目录。

## 1. 决策主线与阶段

先写一句内部工作句：“为实现投资方的什么目标，本次请求对什么对象批准什么动作，前提是什么。”从这句话倒推必要证据。

| 阶段 | 主要问题 | 适当的结论动作 |
|---|---|---|
| 探索/初筛 | 是否相关，值得投入多少研究资源 | 接触、观察、淘汰、补充关键信息 |
| 立项 | 为什么值得尽调，最关键的待证假设是什么 | 批准尽调或试点，明确范围与成功门槛 |
| 尽调/谈判 | 假设是否得到支持，剩余问题能否解决 | 推进谈判、补证、有条件继续或终止 |
| 正式投决 | 在价格、权利义务和风险明确后是否批准交易 | 按明确条件批准、暂缓或否决 |
| 投后评审 | 交付与原目标的差距，下一步如何调整 | 继续投入、纠偏、调整合作或触发已约定安排 |

以上是写作门槛，不是固定审批制度。不套用参考材料中特定机构的审批称谓、审批人、金额上限或年份。也不把尚待谈判的控制权、数据权利和退出安排写成已经取得。

## 2. 三个判断分别成立

| 判断 | 需要的证据 | 不能替代它的材料 |
|---|---|---|
| 公司质量 | 技术成果、产品验证、客户与经济性、团队和持续交付能力 | 名校背景、名人支持、融资新闻本身 |
| 投资方匹配度 | 我方明确需求、双方能力互补、协同机制、承接资源 | 标的单方愿意合作、泛称生态协同 |
| 交易可行性 | 所在阶段需要的价格与融资信息、股权和关键条件、资源与风险边界 | 技术先进、市场很大、合作关系良好 |

公司质量较高但匹配度不足，可以建议其他合作或持续观察。战略匹配较强但价格、权利或技术条件未满足，可以推荐继续谈判。不能用强项抵消决定性负面证据而不给出解释。

## 3. 投资必要性

选择与项目相关的替代方式作同口径比较。不要为了支持投资而把替代方式写得明显不合理。

| 方式 | 要检查的问题 |
|---|---|
| 采购/许可 | 现成产品或服务能否满足目标？缺失的是产品功能还是持续技术输入？ |
| 联合研发 | 合同是否已能获得所需交付、使用权和投入承诺？合作周期和控制程度如何？ |
| 自研 | 时间、人才、数据、资本投入及失败风险是否可接受？ |
| 股权投资 | 投资会增加哪些可实现的资源、治理、长期协作或经济收益？通过什么安排实现？ |
| 暂缓 | 延迟会损失什么机会？等待哪些证据可以提高决策质量？ |

股权投资不天然带来排他合作、源代码访问、数据所有权或团队控制。将这些写为价值时，应有相应条款或明确的待谈判前提。

## 4. 可选页型

### A. 决策摘要

- 问题：本次希望批准什么，为什么，前提是什么？
- 内容：当前推荐动作；最关键的支持理由；决定性风险或未决项；要求批准的范围。
- 表达：一个主判断和少量证据块，可以将方向、标的、投资价值、条件并列。
- 判断标题：结论与动作明确。不得在正文仍有决定性缺口时写成“值得投资、建议批准”。
- 完成顺序：分论点和证据确定后再写摘要；展示顺序可以置前。

### B. 投资目的与替代方案

- 问题：投资方要解决什么问题，为何采取当前动作？
- 内容：目标、现状与缺口、替代方式、投资的增量作用及成立条件。
- 表达：目标到价值机制的因果图，或同维度方式比较。
- 边界：必须先识别投资方，不把“我方平台”当成通用预设。

### C. 方向机会与时机

- 问题：需求来自哪里，为什么现在值得关注，何时可能形成价值？
- 内容：客户任务与约束、市场或技术变化、成熟度、价值实现时间、竞争与采用障碍。
- 表达：需求分层、应用与成熟度矩阵、趋势时间轴。
- 边界：技术前景、可服务市场、付费需求和标的可获得收入是不同概念。预测注明口径和情景。

### D. 技术路线与行业前沿

- 问题：不同路线的优势、代价和适用条件是什么，为什么与本次投资有关？
- 内容：同一任务下的路线机制、数据或工程要求、性能/成本/可控性、成熟度、投资方适配。
- 表达：路线树、同口径对照、代表案例的机制与证据。
- 边界：优先路线不等于行业终局。案例效果、对架构的推断和系统性能实测分别表达。
- 算力类项目可以推导计算、访存、通信与部署；设备、材料、软件等项目选用其实际决定价值的机制。

### E. 标的筛选与竞争比较

- 问题：在合理候选集合中，为什么该公司更适合当前目标？
- 内容：候选范围与筛选依据、相同维度证据、标的强项与弱项、合作与投资可达性。
- 表达：比较表与少量能力证据卡。行业标杆可单列，不强行与可投对象总分排名。
- 边界：维度服从目标。没有原始依据不生成星级或精确评分；缺失证据写未知。

### F. 技术尽调与研发执行

- 问题：当前能力验证到哪一步，目标与现状之间还有什么？
- 内容：测试对象、版本、条件、结果、限制；技术资产与团队贡献；当前结果到未来目标的工作与资源。
- 表达：已验证成果和计划并列；测试表、误差或失败案例、机制图。
- 边界：演示效果不代表量产稳定性；开源使用不等于自研贡献；合作论文不等于独占技术权利。

### G. 经营、团队与经济性

- 问题：企业能否持续交付，业务和资金是否支持所宣称的转型或增长？
- 内容：按相关性选择产品、客户验证、合同与收入、成本和毛利、现金消耗与融资用途、核心人员、股权与权利基础。
- 表达：业务到收入的链条、关键经营指标、团队能力与缺口、资金与里程碑对应。
- 边界：历史业务证明哪些能力、能否迁移至新业务，要单独解释。不要以背景介绍占据全部篇幅。
- 财务型任务增加用户要求的回报情景与估值逻辑，先明确测算假设；不强行沿用产业协同叙事。

### H. 交易、风险与推荐条件

- 问题：当前阶段可以批准到哪里，什么事项会阻断或改变建议？
- 内容：已知与拟议条款、价格依据、融资需求、关键风险、支持与反对证据、验证或缓释安排。
- 表达：风险 → 影响 → 触发或验证条件 → 推荐动作。
- 边界：区分风险、已发生问题和单纯缺资料。“待补充”不足以替代对决策影响的判断。

### I. 投后目标与里程碑

- 问题：投资后获得什么，谁投入资源，如何判断交付？
- 内容：基线、成果或指标、期限、标的责任、投资方承接、双方资源、验收方法、关键依赖。
- 表达：分阶段表格；允许用近期/中期，不机械复制自然年度。
- 边界：目标是计划而非事实。阈值和未达标处理没有依据时，列为待协商项，不冒充承诺或合同。

## 5. 组合与文风

- 按用户页数压缩或展开。若限定页数，优先合并逻辑相邻页面、将详情放备注，不自行增页。
- 建议每页有一个主判断。标题用“对象 + 有依据的判断 + 必要范围”，不要只写“技术分析”“竞争格局”。确实是公司信息或事项清单时，描述性标题也合适。
- 主张写到证据能支持的强度。条件较多时，标题保留关键限制，其他限制放结论带或正文。
- 图形承担逻辑：左右比较、上下因果、阶段演进、同维度表格。图片需说明证明什么。
- 阅读型材料应采用结论前置和证据组合；避免小字、冗长标题、重复页或无出处强判断。

## 6. 交付格式示意

框架：页码、决策问题、判断方向、证据需求、建议结构。判断尚不成立时写待证命题，不伪装成结论。

逐页文案：判断标题、正文、投资含义、必要条件/来源、图表建议。用户要可复制正文时，把制作说明放在正文之外。

审阅：原页或原句位置、问题、为何影响决策、建议替换文字、仍需补证的项目。优先处理推荐越级、关键事实冲突和缺失反证，再处理表达冗余。

HTML：沿用上面的决策结构，将正文与有论证作用的图表组织成可浏览的阅读页；按用户篇幅安排页面，不自动增加封面或展示全部页型。具体离线、导航、放大、依据回看和浏览器检查见 [HTML交付规范](html-delivery.md)。
